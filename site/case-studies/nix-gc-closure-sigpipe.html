Case study: a SIGPIPE in Nix's gc-closure test

Nix's functional test gc-closure.sh can fail with exit status 141. Rewind VM failed it on the first run; the host passed it 200 times. We reported it as NixOS/nix#16546, and the fix below was merged as NixOS/nix#16547.

The test

Lines 14 to 16 of gc-closure.sh split a derivation's two outputs: 

    input2=$(nix build -f dependencies2.nix input2_drv --no-link --print-out-paths)
    input2_out=$(printf "%s" "$input2" | head -n1)
    input2_out2=$(printf "%s" "$input2" | tail -n1)

Meson runs each functional test as bash -x -e -u -o pipefail, so if printf dies the pipeline fails and the test ends.

Run it

The derivation is the functional tests of Nix master 203f85b2, narrowed to this one test (flake). --epoch fixes the VM's clock, which seeds its randomness, so these are the runs you get. Count the writes

rewind cat reads a file in a fork of the run at any step. /proc/<pid>/io counts each process's writes: 

$ for step in 83382 83398 83404; do echo "step $step"; rewind cat 2b0c9595 $step /proc/535/io | grep -E '^(wchar|syscw)' | sed 's/^/  535 /'; rewind cat 2b0c9595 $step /proc/536/io | grep -E '^(wchar|syscw)' | sed 's/^/  536 /'; done
step 83382
  535 wchar: 0
  535 syscw: 0
  536 wchar: 30
  536 syscw: 1
step 83398
  535 wchar: 316
  535 syscw: 2
  536 wchar: 122
  536 syscw: 2
step 83404
  535 wchar: 316
  535 syscw: 3
rewind: /proc/536/io: no such file at this step

The first write of each is its bash -x trace line. At 83382 only head has made it, and waits for input. By 83398 printf has made its trace line and written the first store path, and head has echoed that line, 92 bytes, and exited. At 83404 printf's third write adds no bytes: the pipe has no reader left.

Root cause

bash line-buffers its own standard output, so printf writes one line per write call. On the host, with the same bash and the two paths from the run: 

$ export X=$'/build/nix-test/main/gc-closure/store/ij8qwx0m6dvpmggqmq8zmhbaiw6ym8pg-dependencies-input-2\n/build/nix-test/main/gc-closure/store/hw6dm6rpynd7hmhl1mnp0z4m28lfbx4b-dependencies-input-2-out2'
$ strace -f -e trace=write -o /dev/stdout bash -c 'set -o pipefail; y=$(printf "%s" "$X" | cat)' | grep write
1281845 write(1, "/build/nix-test/main/gc-closure/"..., 92) = 92
1281845 write(1, "/build/nix-test/main/gc-closure/"..., 96) = 96

The buffering is set in shell_initialize in bash 5.3's shell.c. head -n1 exits after the first line. If it does so between the two writes, the second write raises SIGPIPE, pipefail makes the pipeline's status 141, and -e ends the test.

The fix

Give head its input without a pipe, so there is no writer to kill:

-    input2_out=$(printf "%s" "$input2" | head -n1)
+    input2_out=$(head -n1 <<< "$input2")

Line 16 needs no change: tail reads to the end. With the fix, all 65 schedules pass:
